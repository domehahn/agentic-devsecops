For twenty years, "engineering" in software meant designing systems that humans operate. Agentic engineering is the discipline of designing systems that AI agents operate — with humans setting intent, constraints, and review gates instead of every keystroke.

That distinction sounds subtle. It isn't. It changes what you optimize for.

## The shift in unit of work

In traditional engineering, the smallest unit of delivered work is a commit written by a person. In agentic engineering, the smallest unit is a **task delegated to an agent**, which the agent decomposes, executes across multiple tool calls, and reports back on. The engineer's job moves up a layer: from writing lines to writing specifications, guardrails, and evaluation criteria that an agent can act against reliably.

<KeyTakeaway>
Agentic engineering is not "AI writes your code faster." It is a discipline for structuring intent, context, and verification so that autonomous execution is safe and repeatable.
</KeyTakeaway>

## Three properties of agentic systems

1. **Autonomy with boundaries** — agents plan multi-step work themselves, but only within an explicitly scoped tool and permission surface.
2. **Context over instructions** — outcomes depend more on what the agent can see (code, specs, prior decisions) than on how cleverly a prompt is worded.
3. **Verification as a first-class step** — every agent-produced change needs an evaluable definition of done: tests, schemas, policy checks, or human review.

## A minimal scoped-agent policy

Treat an agent the way you'd treat a new, fast, occasionally overconfident engineer: give it a scoped environment, a clear spec, and a pipeline that catches what review misses.

```yaml title=".agent/policy.yaml"
agent_identity: pr-bot
permissions:
  repo_write: scoped(feature/*)
  secrets_access: none
required_checks:
  - unit_tests
  - human_approval
```

<Architecture>
Every agent identity gets its own scoped, short-lived credentials — never the engineer's own. The pipeline enforces this, not convention.
</Architecture>

## Where this fits next to DevSecOps

Agentic engineering doesn't replace DevSecOps — it extends it. Pipelines, policy gates, and least-privilege access controls become the containment system for agent-initiated changes.

<Warning>
An agent with broad write access and a vague task is not "faster development." It's an unreviewed deployment pipeline with a natural-language front end.
</Warning>

| DevSecOps assumption | Agentic reality |
| --- | --- |
| A human wrote this commit | An agent executed a task against a spec |
| Credentials are used by one identity | Credentials may be used by many ephemeral agent sessions |
| Pipeline gates are the last line of defense | Pipeline gates are often the *only* line of defense |
