Generative AI did not invalidate software engineering, DevOps, DevSecOps, or MLOps.

It made their boundaries larger.

A modern AI-enabled application may contain:

```text
application code
model
system prompts
retrieval data
tool definitions
evaluation datasets
guardrails
memory
external APIs
agent workflows
```

Each can influence production behavior.

## Security guidance had to expand

In July 2024, NIST published SP 800-218A, a Community Profile that augments the Secure Software Development Framework with practices specific to generative AI and dual-use foundation models across the software development lifecycle.[^ssdf-ai]

That is a useful historical signal.

The secure-software lifecycle was no longer sufficient when interpreted only around conventional source code.

AI model development and integration required additional practices.

## AI risk also received a generative-AI profile

On the same date, NIST published the Generative AI Profile for the AI Risk Management Framework.[^gai-profile]

This reinforces a broader engineering model:

```text
secure software
+
AI-specific risk management
+
AI evaluation
```

rather than treating generative AI as an ordinary library dependency.

## Outputs are no longer fully specified

Traditional application logic often defines:

```text
if condition:
    return known behavior
```

A generative model produces outputs from a probability distribution conditioned on context.

That changes testing.

Instead of only:

```text
unit test passed?
```

AI engineering also needs:

```text
evaluation distribution
failure rate
safety behavior
robustness
regression across model versions
```

<KeyTakeaway>
When behavior is probabilistic, evaluation becomes part of the implementation—not an optional QA activity after implementation.
</KeyTakeaway>

## Prompts and context become production artifacts

Prompts can change system behavior without changing application code.

So can:

```text
retrieval content
tool descriptions
memory
model version
sampling settings
```

That means versioning and review need to extend beyond source files.

A release may need to identify:

```text
code digest
prompt version
model identity
evaluation result
tool policy
retrieval configuration
```

## Agents increase the consequence of model output

A chatbot produces text.

An agent can use model output to:

```text
read files
call APIs
execute commands
modify systems
send data
```

Anthropic's 2024 engineering guidance distinguishes between predefined workflows and agents in which models dynamically direct their own processes and tool usage.[^anthropic-agents]

The important engineering consequence is not the terminology.

It is that probabilistic model output can now select actions.

That creates a new trust boundary:

```text
model decision
      ↓
capability request
      ↓
real-world effect
```

## DevSecOps becomes necessary but insufficient

Existing security controls still matter:

```text
SAST
dependency scanning
SBOM
provenance
secrets management
runtime monitoring
CI/CD policy
```

AI systems add controls such as:

```text
prompt-injection testing
model evaluation
tool permission boundaries
behavioral testing
AI-specific risk assessment
model and prompt traceability
```

The result is not a separate parallel discipline.

It is a larger engineering lifecycle.

## The direction of travel

Across sixty years, the recurring change is the same:

```text
more behavior moves into the engineered system
        ↓
the engineering boundary expands
```

Programming became software engineering.

Software development expanded into continuous delivery and operations.

Security moved into the lifecycle.

ML added data and models.

Generative AI adds open-ended behavior and, increasingly, autonomous tool use.

The practices accumulate.

That is the lineage from software engineering to AI engineering.
